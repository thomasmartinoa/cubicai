# CubicAI: personal Android AI chat app

Native Kotlin + Jetpack Compose, single `:app` module, package `dev.martin.cubicai`. Personal sideload only (no login, release signed with the debug key).

## Build / install
- `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk` (copy to `CubicAI.apk`)
- `adb install -r app/build/outputs/apk/release/app-release.apk`
- Toolchain: AGP 9.4.1 (built-in Kotlin), Kotlin compose plugin 2.4.21, Gradle 9.8.2, compileSdk 37, minSdk 29, JDK 27. SDK at ~/Android/Sdk.

## Layout
- `data/Settings.kt`: provider presets (Local PC, Gemini, xAI, OpenRouter, Custom), SharedPreferences store. Local PC has a home URL and an optional Tailscale URL (`baseUrls`, tried in order).
- `data/Personas.kt`: built-in behaviours ("None" sends no system prompt). Custom ones live in settings; "About you" is appended to every behaviour except None.
- `data/SecretBox.kt`: API keys and the PC token are AES-GCM encrypted with an Android Keystore key.
- `data/Models.kt`: Chat/Message/Attachment + org.json (de)serialisation. No kotlinx.serialization on purpose. Each chat stores its own persona and model.
- `data/ChatStore.kt`: one JSON file per chat in filesDir/chats, attachments in filesDir/attachments.
- `data/Attachments.kt`: images → downscaled JPEG; PDFs → page images via PdfRenderer; other files → text.
- `net/LlmClient.kt`: OkHttp SSE streaming. `/chat/completions` normally; xAI + Search uses `/responses` with `web_search` + `x_search`. OpenRouter search uses `plugins:[{id:"web"}]`. Falls back across base URLs only on connect failure (a TLS refusal wins over later errors so the "turned away" hint shows). A stream that ends without `[DONE]`/`finish_reason` is an error ("connection dropped"), not a silent cut. Don't shorten the LAN connect timeout: home Wi-Fi with 1 s RTT spikes then fails spuriously.
- `ChatViewModel.kt`: all state (`UiState`), streaming, edit/regenerate, personas, TTS. The whole history is resent each turn; photos only from the last 6 photo messages.
- `WorkService.kt`: foreground service (dataSync, partial wake lock) started while `streaming` (reply or PC job), so leaving the app doesn't freeze the work; its notification says what's going on and has Stop. It stops 2.5 s after the work ends (a picture and the model's look at it run back to back) and, if the app isn't on screen, posts a "finished" notification (cleared when the app shows again). Closing the app from recents clears the ViewModel and stops the work; PC jobs are picked up again on reopen. POST_NOTIFICATIONS is asked once.
- Replies store `took` (ms): text from request to end, PC jobs from `MediaRequest.startedAt` (submit) to the files being here; shown beside the model name. `Settings.thoughtsOpen`: null opens reasoning only while thinking; once the user opens or folds one, every reply follows that.
- `ui/`: Theme (cobalt + amber, Chakra Petch headings, cut-corner shapes), Cube (brand mark + thinking animation), ChatScreen, Messages, Behaviour sheet, Markdown (Markwon; streaming word fade, square bullets), ModelPicker, ContextMeter, SettingsScreen.
- Token usage: requests ask for `stream_options.include_usage`; the reply stores `promptTokens`/`outputTokens`. ContextMeter (beside send) shows last prompt+output against the model's `contextTokens`, estimating ~4 chars/token (marked `~`) when a provider doesn't report counts.

## Gemini
- Chat goes through Google's OpenAI-compatible endpoint (`/v1beta/openai`); default model `gemini-3.5-flash` (3.8 is often overloaded; 2.x models are closed to new keys and hidden from the picker).
- Image creation ("Image" chip, `LlmClient.generateImage`) uses the native `generateContent` API with `responseModalities: IMAGE`. Google's free tier has zero image quota, so it only works with billing enabled; the 429 is turned into a plain-language message.
- No web search for Gemini yet (the compat endpoint lacks grounding).

## Grok (xAI)
- Chat on /chat/completions; with Search on, /responses with `web_search` + `x_search`. `grok-4.20-multi-agent*` (`Provider.isMultiAgent`) always goes to /responses: no function tools (the create tool is left out), search tools only with Search on.
- Grok Imagine: the Image chip posts `/images/generations` (`/images/edits` with the message's photos, up to 5) with `response_format: b64_json`; the Video chip posts `/videos/generations` (6 s, `VIDEO_SECONDS`; 9:16 unless a photo sets the shape), polls `/videos/{request_id}` every 4 s (progress in the status line, 8 misses tolerated) and downloads `video.url` into an MP4 attachment. Request bodies are `xaiImageBody`/`xaiVideoBody`.
- Imagine models show in the picker tagged "makes pictures/videos"; picking one sets `Settings.mediaModels["xai:image|video"]` and turns that mode on instead of becoming the chat model (`Settings.model` ignores a media model stored before this). The Image/Video chips show only their icon until chosen.
- A video's request id is saved on the reply (`Message.cloudJob`) as soon as xAI accepts it (`startXaiVideo`), so leaving the chat or closing the app only stops watching: opening the chat collects it (`followVideo`, `awaitXaiVideo`), Retry after a network error collects instead of paying again, and only xAI's own end (failed, expired, held back, 404: `VideoGoneException`) or Stop drops the id. xAI has no cancel, so Stop just gives the video up.

## Design rules
- Shapes come from `MaterialTheme.shapes` (all `CutCornerShape`); buttons pass `shape = MaterialTheme.shapes.small`. No rounded/circle shapes.
- Headings use Chakra Petch via the typography; body stays Roboto.
- One edge per surface: 16dp page gutter (messages, home, composer box, settings), 20dp inside bottom sheets. Icon buttons that start a row are pulled in by their 12-15dp inner padding so the icon, not the touch target, sits on the edge. Check with `uiautomator dump` bounds, not by eye.
- Menus use `CubicMenu` (raised tone + hairline edge). Selected rows in sheets get a tinted band. Destructive actions (Delete, Unpair) are `colorScheme.error`, including dialog confirms.
- Settings sections are `SettingsCard`s with `SettingRow`; toggles use `CutSwitch` (Material's Switch is pill-shaped). Theme is System/Light/Dark (`Settings.theme`, `isDark()`), and the system bar icons follow it.
- Motion is short (120-260 ms) and tied to state: the cube rolls its light, the phase label shimmers (Thinking, Searching, Writing), streamed words fade in one after another (`StreamFader`, 320 ms per word, alpha only so lines aren't re-measured) while the reply's height eases open, reasoning opens itself while the model thinks (until the user sets `thoughtsOpen`), list items fade in, the send/mic/stop button cross-fades.
- Never put a secret (API key, token) in the repo; keys are entered in Settings and stored encrypted by `SecretBox`.

## Local PC mode (the gateway lives in CubicAI Lab)
- The PC side is `cubicai-gateway` in the CubicAI Lab repo (`~/dev_works/Model_test_harness/cubicai-lab/crates/gateway`, installed at `~/.local/bin/cubicai-gateway`, run by the `cubicai-server` user service; its CLAUDE.md has the internals). CubicAI Lab's Phone tab is its panel (launcher "CubicAI Server"). Until 2026-11-07 it was Python in `server/` here; that was removed once the Rust port had replaced it (still in git history, e.g. commit 2017145; the Lab's golden tests keep Python's recorded answers). Protocol changes go in the Lab repo.
- The gateway: HTTPS, phone → (TLS 1.3, pinned self-signed cert, bearer token) → Ollama on 127.0.0.1:11434. Converts OpenAI chat format ↔ Ollama `/api/chat` (thinking → `delta.reasoning`, `cubic_status` progress events, `citations`, final `usage` from `prompt_eval_count`/`eval_count`).
- Listens dual-stack (`--bind ::`; IPv4 peers unwrapped from ::ffff:). Only loopback + private (home) addresses, plus the PC's own global IPv6 prefixes (`lan6()`, from /proc/net/if_inet6, skipping tailscale/docker/veth), may connect; Tailscale (100.64/10) only while `remote` is on (`cubicai-gateway remote on|off`, or the Lab's Phone tab). Others are dropped before TLS, and the check repeats per request (403) so kept-alive Tailscale connections stop when remote goes off.
- /v1/models includes `cubic_remote` (the Tailscale URL while remote is on); the app adds/updates its stored remote URL from it, never clears it, so no re-pair is needed.
- Connection slots: 64 total, 12 per address. Error responses drain the unread body and close the connection.
- Context: a Modelfile `num_ctx` wins; otherwise settings.json `num_ctx` (default 16384), capped at the model's max. Reported as `context_length` in /v1/models. `keep_alive` 15m.
- Web search runs on the PC via SearXNG in Docker (`cubicai-searxng`, 127.0.0.1:8888, config in ~/.config/cubicai-server/searxng). Request flag `cubic_web_search: true`. Page fetches are limited to public addresses (SSRF guard, incl. redirects).
- mDNS: the server runs `avahi-publish-service _cubicai._tcp 8443 fp=<cert sha256>`. When every address fails (not a TLS refusal, at most once per 30 s) `LlmClient` asks `net/LanFinder.kt` (NsdManager) for a service with the paired `fp`, takes its site-local IPv4 address and stores it as the new home URL. A media job that lost the PC retries as soon as the phone's network comes back (ConnectivityManager callback).
- IPv6 fallback: /v1/models also reports `cubic_lan6` (the PC's IPv6 home URL); the app stores it as `localLan6Url` (never cleared by the PC) and tries home IPv4 → IPv6 → Tailscale. The home router here intermittently stops bridging IPv4 between Wi-Fi clients after a reconnect (heals in ~13 min) while IPv6 works. Verified 2026-11-07 by dropping IPv4 to 8443 at the PC (nftables): Test connection and a chat went through the IPv6 address.
- Media jobs: following and each file download go through `reconnecting` (MEDIA_RECONNECTS, growing waits cut short by the network-back callback). Retry on a reply that still has `media.jobId` collects that job instead of making it again; a job that failed, was stopped or is gone (404) has its jobId cleared so Retry makes it anew. Deleting a chat cancels every job of its replies that has no files yet (running or undelivered). The janitor empties our ComfyUI's history whenever nothing is running (a cancelled run can be recorded after we cleared it).
- `Links` (ConnectivityManager): addresses the phone can't reach now are skipped instantly (100.64/10 and fd7a:115c:a1e0::/48 need a VPN; private IPv4 addresses need Wi-Fi/Ethernet or a VPN; the PC's IPv6 home address needs Wi-Fi/Ethernet, since from mobile data the PC only drops it). The error then says why ("not on home Wi-Fi and Tailscale is off"; with Tailscale on and off Wi-Fi, that it can take a minute to reconnect after leaving Wi-Fi); a "connection refused" says the server isn't running.
- On start the media manager clears the queue and interrupts its own ComfyUI unit, so a job from a previous gateway never saves a file nobody will collect.
- Identity (cert, key, token, settings.json) in ~/.config/cubicai-server (0700). Pairing link `cubicai://pair?u=&r=&t=&f=`; `rotate` revokes phones.
- Emulator reaches the PC at https://10.0.2.2:8443 (`pair --url https://10.0.2.2:8443`).
- Never log message content in the gateway.

## Create on the PC (ComfyUI)
- Gateway `media.rs`: `GENERATORS` (13: image/edit/tool/video/music/speech) map a saved UI workflow + selectors (`#node.input`, `@subgraphInput`) to prompt/seed/size/seconds/image/audio; `fixed` overrides (Chatterbox `repetition_penalty` 1.2: the default 2.0 never stops). Chatterbox's built-in voice drifts between female and male per seed, so speech without a sample uses a reference from `~/.config/cubicai-server/voices/{woman,man}.wav` (request `speaker`; listed as `voices` only when the file exists). Only generators whose model files exist are listed. The job picks its seed up front (0..2^32-1, clamped per node) and reports it; the reply stores it as `MediaRequest.seed` (outside `params`, so Regenerate still varies). `steps`/`cfg` selectors exist only for Qwen 2.1, Illustrious and Wan 5B (distilled models break off CFG 1); `/v1/media/generators` gives the workflow's own steps/cfg/negative as defaults (`_defaults`), and the sheet's "More controls" sends only changed values.
- Gateway `workflow.rs`: UI workflow → API prompt (subgraphs flattened, widget order from `/object_info`, seed-control and upload slots skipped, muted/bypassed/reroute/primitive handled).
- ComfyUI runs as `cubicai-comfyui.service` on 127.0.0.1:8188, started on demand, stopped after `CUBICAI_COMFY_IDLE` (600 s). A running unit is adopted after a server restart. Ollama is unloaded before a job; ComfyUI is `/free`d before the next chat.
- GPU sharing (8 GB card): a job unloads Ollama (`free_ollama`); a chat during a job gets a "busy" status and loads partly on CPU, so `free_for_chat` afterwards also unloads any model not fully in VRAM (else 15 tok/s instead of ~100 for 15 min). ComfyUI start does reset-failed + a second start, since right after a crash systemd still calls the dying unit active. A dropped websocket becomes "ComfyUI stopped while making this". On server start, queued/running work in our ComfyUI unit is cleared.
- One job at a time. Routes: `GET /v1/media/generators`, `POST /v1/media/jobs` (base64 image/audio), `GET …/jobs/<id>/events` (SSE, previews as base64), `GET …/files/<n>` (after the last file the job is forgotten), `DELETE …/jobs/<id>`, `POST /v1/media/save?kind=&name=`.
- Temp policy: results in ~/.cache/cubicai-server/media until downloaded (TTL 1 h); ComfyUI input/output `cubicai/` emptied per job and at start; `--disable-metadata`. Saved copies go to /mnt/storage/games/AI_local/CubicAI/{Images,Videos,Music}.
- App: `net/MediaClient.kt`, `ui/CreateSheet.kt` (Create chip, Local PC only), `ui/Media.kt` (progress card, video/audio players, share). A reply's `media` (generator, params, jobId) lets it resume after a drop or app restart, Stop cancels on the PC, deleting a chat cancels its jobs. Media replies reach chat models as a one-line note. A generator that needs a photo uses the latest picture in the chat when none is attached (chained edits). The sheet preselects the last choice (`Settings.lastCreate`); create mode itself is not restored on start. Progress weights nodes by cost (`_weight`), previews arrive from the first sampling step.

## Chat models making things (create tool)
- Chat models get a `create` tool (OpenAI function format; xAI's Responses API gets the flat shape) when the PC is paired, its generators are known (`creationGenerators`, asked again at most once a minute) and the model takes tools (`supported_parameters` in /v1/models; unknown counts as yes, and a 4xx that mentions tools retries without them, the history's calls then sent as notes). It offers picture generators (create mode, with `PROMPT_GUIDES`), voice (speech), music (ACE-Step: style prompt, `lyrics` with section labels turned into `[verse]`/`[chorus]`, `seconds`) and video.
- Video: the call makes a reply with `MediaRequest.ask` (a "Make a 4 s video?" card; nothing runs). Yes (`answerVideo`) takes the latest picture (`start_from: last_picture`) or inserts a picture reply before it (`for_video` = the video's id, call-less, left out of the model's history); when that's done the video (Wan 14B, shape from the picture) gets `source` and starts. No, or sending another message, marks it `declined` (stopped; "Make it now" runs it). Stop stops the picture and the video together; `resumeMedia` resumes whichever of them is on the PC.
- A call becomes a media reply whose `MediaRequest.call` keeps it. Params carry app-only `auto`, `source` (a face or the last picture) and `voice` (sample path), stripped before submitting. Voice messages also send `speaker` (the model's pick, else guessed from the behaviour's words); emoji and *stage directions* are dropped from the words. After a voice message the tool result tells the model to go back to text (it otherwise answered everything by voice). `shows_you` with a face → Qwen Edit 2511 from the face; `start_from: last_picture` → an edit of the latest picture; otherwise the named generator (z-image by default). The model's negative goes after the workflow's own.
- History: the call goes on the assistant text just before it, then a `tool` result (`creationResult`), then, for models that see creations (local vision models and Grok; other cloud models never get the pictures), the picture as a user message marked as the model's own (JPEG ≤ 1024 px). At most 2 creations per user message (`tool_choice: none` after that; the gateway then leaves tools out).
- After a picture, a model that sees it gets another turn (look, carry on, or try once more); a voice message or a picture it can't see ends the turn. A follow-up that is empty or only a bracketed stage direction is dropped. A reply that only announces a picture (`ANNOUNCED`, English) without calling gets one nudge request.
- Characters: `Persona.looks/facePath/voicePath/sendsOnItsOwn`, and `Chat.facePath/voicePath` as the chat's own copy (falls back to the behaviour's). Files in filesDir/characters: `chat-<id>-…` go with the chat, `persona-<id>-…` with the behaviour. The first picture with `shows_you` becomes the chat's face; "Use as face" on a picture; "Save to <behaviour>" in the Behaviour sheet.
- UI: a "Prompt" fold-out (`ModelPrompt`) on such replies with "Edit and make again" (`remakeWithPrompt`, a new reply).
- Gateway: passes `tools` to Ollama for models with the `tools` capability and converts tool calls both ways (Ollama's arguments are objects; ids `call_<rid>_<n>`).
- Small models (Gemma E4B) call the tool well from context and keep the character consistent, but rarely retry a wrong picture: they adapt the story to it instead.

## Voice calls
- Grok-style live call in the open chat (GraphicEq button beside the mic; needs the PC paired or an xAI key). The PC is ears and mouth, the phone the brain: the gateway's `voice/` on `GET /v1/voice/call` (WebSocket, its own RFC 6455). Phone sends 16 kHz PCM16 binary frames + JSON (`start`/`config` voice, speed, patience; `say`/`say_end` per `turn`; `cancel`; `playing`). PC sends `status`, `ready`, `speech` on/off, `partial`, `final`, `seg` (sentence) followed by 24 kHz PCM16 binary, `turn_end`.
- All CPU/ONNX so Ollama keeps the GPU: Silero VAD (frame by frame, stricter while the phone plays), Parakeet TDT 0.6B v3 int8 (partials only while voiced and the transcriber is idle, so the final never waits), Kokoro v1.0 (system espeak-ng; sessions without thread spinning, else ASR slows TTS). Models and ONNX Runtime in ~/.local/share/cubicai-server/voice via `cubicai-gateway voice-setup`. Loaded on the first call (~2 s), unloaded after 15 min without one. ORT telemetry is disabled. `/v1/voice/voices`, `/v1/voice/preview` (PCM), `/v1/models` `cubic_voice`.
- Measured: final transcript ~0.5 s after the user stops (600 ms pause default, `callPatience`), first sentence voiced ~0.7-1 s after the reply's first sentence arrives.
- App: `call/CallController` (state, turn-taking, check-ins, reconnect), `call/CallAudio` (AudioRecord VOICE_COMMUNICATION + AEC/NS, AudioTrack with heard-sentence tracking, pause/flush), `call/CallService` (FGS microphone|mediaProjection, Mute/End, holds `ScreenGrab`), `net/VoiceLink`, `ui/CallScreen` (also `CallBar` when minimised, `VoiceSheet`, `CallOptions` shared with Settings → Voice calls).
- The reply is the normal `complete()`: call guidance added to the system prompt (also for None), `cubic_think: false` (gateway sends `think:false` to every model), no voice-message kind in the create tool, tools only if `callMakesThings`. Text deltas go to `call.onReplyText(turn)`. Messages get `spoken`.
- Barge-in: speech start pauses the voice; a real final transcript cuts the reply (cancel job, keep only heard sentences + " —", drop it if nothing was heard); empty/filler/echo (≥60% words of what was playing) resumes. Talking while something is made: the message is kept, "One moment…" once, answered when streaming ends (`answerWaitingCall`). A spoken yes accepts a pending video ask.
- Camera (CameraX PreviewView, COMPATIBLE so `bitmap` works) or screen (MediaProjection, ~2 fps kept) frame is attached as a photo to each spoken message, and to check-ins (transient). Check-ins (`callCheckIns`, seconds, max 2 in a row, not while muted) send a hidden user note, never with web search (it only made the voice late).
- Grok calls (`Settings.callEngine`: `auto` = PC if paired and `Links` can reach it, else Grok when an xAI key exists, and a PC call that fails its first connect switches to Grok; `pc`; `grok`): `net/GrokVoice.kt` opens `wss://api.x.ai/v1/realtime?model=grok-voice-latest` (Bearer key) and streams the mic as base64 16 kHz PCM (`input_audio_buffer.append`); xAI does VAD (`server_vad`), transcription, the reply and 24 kHz PCM speech. The first `session.update` (`grokSession`) has only documented fields (instructions, voice, turn_detection with `idle_timeout_ms` = check-ins, audio formats + speed, web/X search tools when Search is on); the pause length goes in a second update (`grokTurnUpdate`, OpenAI's `silence_duration_ms`) whose error is ignored, since an invalid update keeps the old config. Instructions = the behaviour's system prompt + call guidance + the chat so far as a transcript (last ~8000 chars). Events: `response.created`/`output_audio.delta`/`done` feed `CallAudio` on the socket thread; transcription `completed` → `grokHeard` (inserted before a reply already started), `output_audio_transcript.delta` → the reply's text; `speech_started` during a reply flushes the audio and sends `response.cancel`, and the reply gets " —". No camera/screen (xAI's voice takes no images), no create tool. Voices from `GET /tts/voices`, previews from `POST /tts` (PCM 24 kHz); per behaviour in `callVoices["grok:<id>"]`, default eve/rex by the PC voice's gender. Replies are stored with model `grok-voice-latest`. Tested on the phone 2026-11-07: hears, answers, checks in, Auto picks PC at home and Grok off Wi-Fi.
- Built-in voice characters (Friend, Conspiracy, Unhinged 18+, Romantic 18+, Therapist, Doctor, Motivator, Argumentative, Meditation, Language tutor, Trivia host) with `Persona.voice`/`adult`; `Settings.callVoices` keeps a voice per behaviour.

## Notes
- All providers are treated as OpenAI-compatible; adding one = new entry in `Providers`.
- Messages list uses `reverseLayout` to stay pinned to the bottom while streaming.
- Drawer search shows from 6 chats, matches titles and message text from the start of a word; it clears (and drops focus) when the drawer closes.
- README screenshots live in docs/screenshots (540 px wide, taken with the SystemUI demo-mode status bar, no personal content).
